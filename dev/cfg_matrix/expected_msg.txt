# cfg_matrix substring contract.  Same format as dev/cli_matrix/expected_msg.txt:
#
#   <scenario_id> <probe>/<stream> <op> <substring...>
#
# <probe> in {doctor, check, plan}; <stream> in {stdout, stderr}.
# <op> in {+, -, =N}: must-appear / must-NOT-appear / exact-count.
#
# Pins the four regressions caught by the first cfg_matrix sweep so they
# stay fixed:
#   B1  — MySQL+TLS panic when mysql crate built without TLS feature.
#   B2  — chunked auto-resolves chunk_column silently from PK.
#   I3  — query_file path traversal only caught at plan time.
#   I4  — `rivet check` skipped destination credential preflight.

# ── B1: MySQL TLS no longer panics, modes resolve appropriately ───────────
# rc=0 was rc=101 (panic) before; now connects cleanly under tls.mode=require.
b07_my_tls_require   doctor/stderr - panicked
b07_my_tls_require   check/stderr  - panicked
b07_my_tls_require   plan/stderr   - panicked
b08_my_tls_verify_ca doctor/stderr - panicked
b09_my_tls_verify_full doctor/stderr - panicked

# ── B2: chunk_column auto-resolve emits visible WARN ──────────────────────
g18_chunked_no_column plan/stderr + chunk_column not set

g18_chunked_no_column plan/stderr + Set `chunk_column:` explicitly

# Sanity: when chunk_column IS set, the auto-resolve warning must NOT fire.
c06_chunked_parquet  plan/stderr - chunk_column not set

# ── I3: query_file traversal/absolute path rejected at config-load ────────
# All three probes must catch the bad path; previously only plan did.
# doctor prints the finding through its own report (stdout) and leaves a
# pointer on stderr — `doctor: config check failed (see output above)`.
# src/preflight/doctor.rs:88 says why: "surface the config error exactly
# once". check/plan, which have no report, still put it on stderr.
g16_query_file_traversal doctor/stdout + query_file path must not contain '..'
g16_query_file_traversal check/stderr  + query_file path must not contain '..'
g16_query_file_traversal plan/stderr   + query_file path must not contain '..'

# ── I4: `check` now performs destination credential preflight ────────────
d03_dest_s3 check/stderr + destination preflight failed
d03_dest_s3 check/stderr + AWS_ACCESS_KEY_ID

# ── Credential / transport warnings: both were NARROWED on purpose ───────
# These two lines used to assert the warnings fire here. They no longer do,
# and in both cases the code is right and the expectation was left behind:
#
#   * plaintext password — src/config/source.rs warns only for
#     `UrlSource::InlineYaml`, i.e. a password committed in the YAML. These
#     fixtures use `url_env:`, which is the RECOMMENDED form; scolding an
#     operator who already moved the secret out of the file is a false alarm,
#     and the code says so at the match arm.
#   * TLS — src/source/mod.rs::warn_if_tls_disabled exempts loopback hosts,
#     because on 127.0.0.1 the bytes never leave the box. The matrix connects
#     to 127.0.0.1. It still fails OPEN: a URL it cannot resolve warns anyway,
#     so the CWE-319 signal survives for every remote host.
#
# Both are asserted here as must-NOT-appear so the narrowing itself is pinned:
# if either warning starts firing on the recommended form or on loopback, the
# false alarm comes back and this contract catches it.
c01_full_query_parquet plan/stderr - source URL contains plaintext password
c06_chunked_parquet    plan/stderr - TLS is not enforced
