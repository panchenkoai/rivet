- **A stop caused by another live rivet process exited 5, "a human decides", while its remedy was to wait and run again.** `RIVET_STATE_RUN_IN_PROGRESS` (a run, `apply`, a CDC drain, `rivet state reset*` or `rivet repair` beside a live run of the export), `RIVET_LOAD_TABLE_BUSY` and `RIVET_STATE_LEASE_LOST` (a `rivet load` or `rivet compact` beside another of the same table) exited 5, so a scheduler that does not retry a refusal (the Airflow provider, cron with retries keyed on the exit code) failed the task for good, although the same command succeeds once the other process ends (an overlapping trigger, an orphaned child of a killed parent). **Behaviour change:** these stops now have the kind `busy` and exit 2 (retryable); the codes and the texts are unchanged, the stop still writes nothing, and a load's ledger still records it as `refused`. A stop about what a dead run left behind keeps exit 5. **What to do:** a scheduler that branches on these codes needs no change; one that branches on exit 5 to catch an overlap matches exit 2 with the code instead.
