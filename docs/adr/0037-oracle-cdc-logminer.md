# ADR-0037: Oracle CDC through LogMiner

- **Status:** Proposed (preview)
- **Date:** 2026-09-28
- **Context:** rivet reads Oracle in batch (preview, #309) but has no change capture from it. Every other CDC engine rivet supports reads a log the database keeps for its own purposes: the WAL (PostgreSQL), the binlog (MySQL), the change tables (SQL Server), the oplog (MongoDB). Oracle's equivalent that ships with every edition, Free included, and needs no separate licence is LogMiner over the redo logs. This ADR fixes how a bounded, checkpointed rivet run reads it, before the adapter is written.

---

## Decision

| ID | Name | Statement |
|----|------|-----------|
| **OR1** | Where to mine | From `CDB$ROOT` with a common user holding `LOGMINING` and `EXECUTE_CATALOG_ROLE`, calling `SYS.DBMS_LOGMNR`. The URL names the PDB's service, so one URL serves the snapshot, the schema probe and the capture: the session resolves the tables in the PDB, then switches with `ALTER SESSION SET CONTAINER = CDB$ROOT` (measured: session NLS settings survive the switch). Rows are filtered to the PDB by `SRC_CON_NAME` (measured: `SRC_CON_DBID` is 0 on every row). Per-PDB mining (19c RU10+) is not used: its user is provisioned through `DBMS_GOLDENGATE_AUTH`, and "GoldenGate per-PDB Change Capture" is not licensed on Free. |
| **OR2** | Prerequisites, checked | ARCHIVELOG mode, database-level minimal supplemental logging, and `ALL COLUMNS` supplemental logging on every captured table (table-level, or `SUPPLEMENTAL_LOG_DATA_ALL` database-wide). The run's open and `doctor` read `V$DATABASE.LOG_MODE`, `SUPPLEMENTAL_LOG_DATA_MIN` and `ALL_LOG_GROUPS` and refuse a missing one with the statement that enables it. `PRIMARY KEY` logging is not enough: an UPDATE's redo then carries only the key and the changed columns, and a rivet change is a whole row (the `RowImage::Partial` refusal). `ENABLE_GOLDENGATE_REPLICATION` is never set (it requires a GoldenGate licence). |
| **OR3** | Tables LogMiner ignores | Oracle documents a table with an identity column, a BFILE, a nested table or temporal-validity columns as "entirely ignored" by LogMiner; capturing one would deliver nothing, silently, so `rivet check` and the run's open refuse it by name. Measured exception: on 23ai Free an identity-column table IS mined (its INSERT surfaces with `STATUS 0`), so the identity refusal applies below 23 only, until measured there. Names over 30 characters are refused (they surface as `UNSUPPORTED`). |
| **OR4** | Dictionary | `DICT_FROM_ONLINE_CATALOG`: no dictionary build to schedule or retain. A column added mid-window decodes against the current shape; redo from before an ALTER can surface with `STATUS` 2/3 — the run refuses such a row (schema drift, `on_schema_drift`) rather than emitting it. |
| **OR5** | Log selection | `CONTINUOUS_MINE` is desupported since 19c. Each run adds the files covering `[start, end]` itself: archived logs from `V$ARCHIVED_LOG` (`STATUS='A'`, `DELETED='NO'`, `NAME` not null, current `RESETLOGS_CHANGE#`, one `DEST_ID`), then the online groups not yet archived from `V$LOG`/`V$LOGFILE`, never both copies of one sequence. |
| **OR6** | Commit framing | `COMMITTED_DATA_ONLY`: transactions arrive whole, contiguous, in commit order, rolled-back work removed. A change of `XID` between consecutive rows is the transaction boundary, so COMMIT rows are not fetched; rows are ordered within a transaction by `SEQUENCE#` (measured distinct per row, even inside one multi-row statement); only the last row is `committed`. The sink never rolls a part mid-transaction (unchanged invariant). The transaction is buffered client-side under the shared `RIVET_CDC_MAX_TX_ROWS` / `_BYTES` caps, which refuse loudly; a transaction too large for the server's staging memory fails the mine with Oracle's own out-of-memory error. |
| **OR7** | Values | Typed column values come from `DBMS_LOGMNR.MINE_VALUE(REDO_VALUE|UNDO_VALUE, …)` with `COLUMN_PRESENT` to tell NULL from absent, never from parsing `SQL_REDO`. The mining session pins `NLS_DATE_FORMAT`, `NLS_TIMESTAMP_FORMAT`, `NLS_TIMESTAMP_TZ_FORMAT`, `NLS_NUMERIC_CHARACTERS` and `TIME_ZONE` to fixed ISO forms (the session-state rule). LOB, LONG, ADT and collection columns are not captured in the preview; a table carrying one is refused (OR3's rule). |
| **OR8** | The bound | `until_current` pins `V$DATABASE.CURRENT_SCN` once at open and passes it as the inclusive `endScn`; the current online group is added so the bound is reachable. |
| **OR9** | The checkpoint | Measured on the stand: a transaction whose first row precedes a checkpoint SCN and whose commit follows it LOSES that first row when the next run mines from `checkpoint + 1` — only the post-checkpoint row comes back (`START_SCN` 0). So the checkpoint holds two SCNs: `commit_scn`, the last commit whose rows are durable, and `low_water`, the lowest `START_SCN` of a transaction still open at that commit. A run mines from `low_water` and drops commits `<= commit_scn`, so a transaction that started before the checkpoint and committed after it keeps its early rows (the change filter is on each row's SCN, not its commit's). |
| **OR9a** | The frontier | The NEXT run's `low_water` is pinned at open as `LEAST(MIN(V$TRANSACTION.START_SCN), CURRENT_SCN)`, read IN THE PDB and BEFORE the bound (measured: from `CDB$ROOT` a common user's `V$TRANSACTION` holds only the root's rows, so a root-side read silently dropped the early row of a transaction open across two runs — `oracle_cdc_transaction_open_across_a_run_keeps_its_early_rows` went RED on exactly that), so every transaction open at the bound started at or after it. Checkpoints written mid-run keep the run's own `low_water`; once the drain is exhausted and every emitted commit is acknowledged, the adapter writes `{low_water, commit_scn: bound}` itself. Without that an idle table would keep an old `low_water` until the archives it needs are purged, and then refuse as a loss. A first open with no checkpoint persists the same pair at once (the idle-first-run rule). |
| **OR10** | Anchor and identity | The anchor is client-side, as MySQL's is. The checkpoint records `DBID`, `DB_UNIQUE_NAME`, `RESETLOGS_CHANGE#` and the PDB's name and `CON_DBID`; a mismatch refuses the run (the class ADR-0012 M10 fixed for MySQL). |
| **OR11** | Anti-gap | Before mining: refuse when `low_water` is below the oldest available log's `FIRST_CHANGE#` in the current incarnation, or a thread's sequence chain has a hole. After starting: `V$LOGMNR_LOGS.STATUS = 4` or any `MISSING_SCN` row is fatal. The message states a data loss and the lossless remedy (re-snapshot BEFORE re-anchoring is the lossy order; the product's own order is anchor, then snapshot). Retention is reader-independent — nothing pins the archives for rivet. |
| **OR12** | Never | `SKIP_CORRUPTION` (silently skips corrupt blocks) and `ENABLE_GOLDENGATE_REPLICATION` are never set. |

## Measured on the stand (gvenzl/oracle-free:23, 2026-09-28)

- ARCHIVELOG and minimal supplemental logging enable on the image (`LOCATION=` under the data volume; mount, archivelog, open, open the PDBs).
- A common user with `CREATE SESSION`, `LOGMINING`, `EXECUTE_CATALOG_ROLE`, `SET CONTAINER` and `SELECT` on `V_$DATABASE`, `V_$ARCHIVED_LOG`, `V_$LOG`, `V_$LOGFILE`, `V_$LOGMNR_CONTENTS`, `V_$LOGMNR_LOGS` mines from `CDB$ROOT` with `DICT_FROM_ONLINE_CATALOG + COMMITTED_DATA_ONLY`, and `MINE_VALUE` returns per-column values.
- Transactions arrive whole, in commit order; a row rolled back to a savepoint is absent; `SEQUENCE#` orders rows within a transaction (two rows of one transaction shared one SCN in reverse order).
- With `PRIMARY KEY` supplemental logging a DELETE carries only the key (in `UNDO_VALUE`) and an UPDATE the key and the changed columns; with `ALL COLUMNS` logging an UPDATE's redo and a DELETE's undo carry every column (`COLUMN_PRESENT` 1), hence OR2.
- `MINE_VALUE` renders by session NLS (`27-SEP-26 10.11.12.123456 AM` under the default) — OR7's pin is required; the adapter's session-state test asserts the pinned rendering.
- Pinned, `MINE_VALUE` still renders NUMBER as `-.5`, a bare NUMBER in scientific form (`1.00…0E+125`), BINARY_DOUBLE as `1.5E+000`, RAW as lower-case hex, and a `TIMESTAMP WITH LOCAL TIME ZONE` with an empty fraction (`…03.`). The adapter canonicalises numbers to the batch export's plain form and parses the rest; the live type matrix compares every captured value with the batch export of the same table.
- `SEQUENCE#` is distinct per row within a transaction, including the rows of one multi-row INSERT; COMMIT rows carry the PDB's `SRC_CON_UID` and `SRC_CON_NAME`, and `SRC_CON_DBID` is 0 throughout.
- OR3's identity exception and OR9's lost first row, as stated above.
